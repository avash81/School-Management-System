## Requirement-to-test preparation checklist

- [ ] Requirements have stable IDs, owner, priority/release, and decision status.
- [ ] Candidate, duplicate, and unresolved reference decisions are recorded.
- [ ] Every retained requirement traces to use case, rule, entity, API, UI, test, and release evidence.
- [ ] Test environment matches the target service boundaries and deployment dependencies.
- [ ] Sanitized test data covers realistic schools, academic years, users, classes, enrollments, exams, and marks.
- [ ] Separate role accounts exercise allowed and denied operations, including cross-school access.
- [ ] Lifecycle, correction, approval, concurrency, audit, and history cases have pass criteria.
- [ ] AI/import and document cases prove review gates, provenance, private access, and failure behavior.
- [ ] Performance, accessibility, localization, recovery, migration, and operational acceptance criteria are measurable.
- [ ] Test outcomes, defects, evidence, and accountable approvals are recorded.

Formal end-to-end testing is not considered ready until the relevant design and test-preparation
criteria above are approved. Any core workflow or security-boundary failure blocks its release.
