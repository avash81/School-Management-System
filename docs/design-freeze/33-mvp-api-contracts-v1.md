# CR-03 — MVP API Contracts v1.0

**Status:** REMEDIATION DRAFT. Base path is `/api/v1`; all payloads are JSON except multipart upload. This document supersedes the summary catalog in Document 21 for MVP endpoints. It is intentionally derived after Documents 30–32.

## Global contract

Authenticated endpoints use secure HTTP-only session cookies or a bearer access token, enforce tenant/permission/scope server-side, and return the authenticated school’s data only. Mutations require `If-Match: <rowVersion>` for an existing aggregate and `Idempotency-Key` for create/queue operations marked below. Unknown fields are rejected.

```json
{ "data": {}, "meta": { "correlationId": "uuid" } }
```

Failures use `{"error":{"code":"MARK_RANGE","message":"...","fields":{"markValue":"..."}},"meta":{"correlationId":"uuid"}}`. Codes are stable; messages are safe to show. `401` authentication, `403` permission/scope, `404` tenant-hidden resource, `409` stale/duplicate/idempotency conflict, `422` lifecycle/business validation, `429` rate limit, `503` dependency unavailable.

All successful mutations record `audit_logs`; all queued mutations also create `job_runs`/outbox event in the same transaction. List endpoints accept bounded `limit` (1–100) and `cursor`; response meta has `nextCursor`.

## Contract completion criteria

Before CR-03 is complete, every endpoint above must have OpenAPI 3.1 machine-readable schemas generated from the same validation DTOs, example success/error bodies, rate-limit policy, permission/scope test and audit event name. Any endpoint for an `R1/F` requirement is excluded from the MVP OpenAPI file until it is promoted through change control.
