# CR-01 — Authoritative Database Specification v1.0

**Status:** REMEDIATION DRAFT — authoritative for database design once approved; it does not authorize a Phase 14 architecture freeze.  
**Supersedes for database detail:** the high-level tables in Document 06 and the non-authoritative dictionary in Document 18.  
**Implementation reference:** `packages/database/prisma/schema.prisma` is pre-freeze scaffolding. It must be reconciled with this document by controlled migrations; it is not the source of truth.

## 1. Decisions fixed by this specification

| Topic                  | Contract                                                                                                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Database               | PostgreSQL 16+; `uuid` primary keys generated by the database/application UUID generator.                                                                                                                                        |
| Naming                 | Snake-case physical table/column names. Timestamps are `timestamptz`, ordinary academic calendar values are `date`, amounts/scores are `numeric`, never `float`.                                                                 |
| Tenancy                | Every school-owned table has non-null `school_id`. Every tenant-scoped query must include `school_id`; composite tenant-consistent foreign keys are used for critical data. Platform rows are the only exception.                |
| Historic truth         | Approved marks, published results, configuration releases and generated official documents are append-only/versioned. They are never updated in place to change history.                                                         |
| Deletion               | Default is soft deletion (`deleted_at`) for mutable operational masters. Academic records, marks, results, snapshots, audit, document history and import evidence are retained/archived, not soft-deleted by ordinary workflows. |
| Optimistic concurrency | Mutable aggregate roots have `row_version bigint not null default 1`; every update supplies the last seen version. A mismatch returns `409 CONFLICT` and writes no mutation.                                                     |
| Audit                  | All security-sensitive and official mutations write an append-only `audit_logs` row in the same transaction. Audit values are JSONB and redact secrets.                                                                          |
| Referential actions    | `ON UPDATE RESTRICT` everywhere. `ON DELETE RESTRICT` is the default. `CASCADE` is permitted only for disposable dependent rows that have no independent history (role grants, session tokens, draft upload derivatives).        |
| Time/localization      | UTC instants in `timestamptz`; a school IANA time zone is stored in configuration. AD/BS renderings are presentation values, never the sole stored date.                                                                         |

## 2. Database domains and global constraints

`30a-authoritative-data-dictionary-v1.md` lists every target table and column. Unless a table explicitly says otherwise, it includes:

```text
id uuid PK; school_id uuid NOT NULL; created_at timestamptz NOT NULL DEFAULT now();
updated_at timestamptz NOT NULL DEFAULT now(); row_version bigint NOT NULL DEFAULT 1;
deleted_at timestamptz NULL
```

`school_id` is omitted only from platform/global reference tables (`permissions`, supported locale registry if introduced) and is nullable only for platform users/audit events. `updated_at` and `row_version` are omitted from append-only evidence/history tables.

All FK pairs with a tenant-owned parent are implemented as `(school_id, parent_id) REFERENCES parent(school_id, id)`, backed by a unique `(school_id,id)` constraint on the parent. This prevents a row from tenant A referring to an ID in tenant B even if an application filter is defective.

### Required PostgreSQL checks

| ID         | Check                                                                                                                                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| DB-CHK-001 | Academic/end dates are not before start dates; exam end is not before start.                                                                                                                                             |
| DB-CHK-002 | Capacity, order indexes, marks maxima/minima and credit values are non-negative; `minimum_age <= maximum_age` when both are set.                                                                                         |
| DB-CHK-003 | A numeric mark is within `0..component.max_marks` at service validation; a DB constraint enforces non-negative value. Exact maximum needs a trigger or application transaction because it is cross-table.                |
| DB-CHK-004 | `attendance_status = present` requires a numeric mark once submitted/approved; absent/exempt/missing states cannot silently be persisted as zero.                                                                        |
| DB-CHK-005 | Percent/GPA/score numeric precision uses `numeric(10,4)` during calculation; published display values are derived by policy, not destructive rounding.                                                                   |
| DB-CHK-006 | At most one active primary guardian per student; at most one active enrollment per student/year; at most one active default configuration release for a configuration kind/school. Partial unique indexes enforce these. |
| DB-CHK-007 | A published/locked result must reference an immutable result snapshot and result-policy release.                                                                                                                         |
| DB-CHK-008 | `file_size_bytes >= 0`; upload and generated-document checksums are SHA-256 hexadecimal and storage keys are tenant-prefixed.                                                                                            |

### Parent deletion/lifecycle rules

| Parent                                   | Children                                        | Action                                                                                                                                         |
| ---------------------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| School                                   | all tenant data                                 | `RESTRICT`; school exit uses a retention/tenancy-offboarding process, never cascade.                                                           |
| User                                     | roles, sessions, authored records               | roles/sessions `CASCADE` or revoke; historical authored references `SET NULL` only where author identity may be removed, otherwise `RESTRICT`. |
| Student/enrollment                       | marks, results, documents                       | `RESTRICT`; archive only.                                                                                                                      |
| Academic/class/section/subject/blueprint | offerings, assignments, exams, historical marks | `RESTRICT`; supersede by new version.                                                                                                          |
| Exam/exam subject                        | marks/results/snapshots                         | `RESTRICT`; archive only.                                                                                                                      |
| Upload                                   | OCR/import evidence                             | `RESTRICT` after processing; original file retained under retention policy.                                                                    |
| Template/version                         | official documents                              | `RESTRICT`; retirement changes active selection only.                                                                                          |

## 5. Reconciliation rules for current schema

1. Do not add foreign-key relations blindly to the existing Prisma schema. First add tenant composite keys/indexes, backfill and validate orphan checks, then add `NOT VALID` constraints, validate, and only then make them required.
2. `Student.academicId` is renamed to `external_academic_id` or removed after data migration. It cannot be used as a per-school unique academic identity without a documented issuer/type. The canonical school record identifier is `admission_no`; external registration numbers belong in an `student_identifiers` table with identifier type/issuer.
3. URL columns (`logo_url`, `photo_url`, `file_url`, `signature_url`) are deprecated in favour of `file_object_id`; signed download URLs are generated at read time and never stored as public data URLs.
4. `ExamStatus`, `MarkStatus`, `ResultStatus`, upload/import/job/document enums are expanded/replaced only through a reviewed migration, preserving legacy values. The formal state machines in Document 13 and the policy in CR-04 will determine the final enumerations.
5. All `Float` confidence fields become `numeric(5,4)` with a `0..1` check. JSON payloads are `jsonb` with a documented schema/version.
6. `Result` becomes a stable aggregate header. `result_snapshots` and `result_subjects` retain calculated values, policy release, source-mark revision set and input fingerprint. A correction creates a new snapshot/version; it never updates a published snapshot.

## 6. Index and query policy

Every tenant table has an index beginning with `school_id`; common list indexes also include lifecycle/status and relevant time, e.g. `(school_id, status, created_at DESC)`. Large list API queries use keyset pagination ordered by `(created_at,id)` or domain sort plus ID. Fuzzy student/teacher name search uses `pg_trgm` lower-cased generated search columns, limited by `school_id`; it does not expose cross-tenant global search. JSONB is not used for fields that must be joined, constrained, or regularly filtered.

## 7. Migration sequence

| Wave | Change                                                                                                                    | Exit criterion                                             |
| ---- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| M0   | Backup, restore rehearsal, schema/data inventory; write orphan and duplicate reports.                                     | Approved report, no unowned production assumptions.        |
| M1   | Introduce domains, new enums/tables, `row_version`, audit correlation metadata and tenant composite keys without removal. | Migration reversible/expand-only and test data backfilled. |
| M2   | Backfill identifiers/file objects/configuration releases; dual-write from services where needed.                          | Reconciliation counts and checksums match.                 |
| M3   | Add FK/check/partial-unique constraints as `NOT VALID`, remediate exceptions, then validate.                              | Zero unexpected violations.                                |
| M4   | Switch reads/writes to versioned/reference tables; enable concurrency conditions and append-only guards.                  | Integration and migration tests pass.                      |
| M5   | Stop dual-write; retain legacy columns read-only for one release; remove only after retention/rollback window.            | Explicit change approval and backup verified.              |

No raw production DDL, destructive migration, or mass cascade is permitted. Each migration must carry owner, forward path, rollback/compensation plan, duration, lock estimate, verification query, and audit record.

## 8. CR-01 completion criteria

CR-01 is complete only when this specification is approved, every listed target entity is represented in the data dictionary, the Prisma schema/migrations pass automated schema verification, and tests prove tenant FK enforcement, lifecycle restrictions, optimistic concurrency, result snapshot immutability, file privacy and import idempotency. Until then, status remains **DESIGNED — remediation in progress**, not implemented or frozen.
