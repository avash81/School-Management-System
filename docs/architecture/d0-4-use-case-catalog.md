# D0.4 — Full Use Case Catalog

## Status

**Planning artifact; no implementation authorization.** This catalog expands the D0.4 model module by module. The later D0.5 specifications will turn the highest-risk entries into detailed executable flows.

## Common use-case contract

Unless stated otherwise, every use case requires an active authenticated account, selected school tenant, permission and resource-scope evaluation, request validation, and audit logging for sensitive/mutating actions. All school data is tenant-scoped. “Assigned” means the teacher’s active year/class/section/subject/exam assignment; “own/linked” means a student’s own record or a verified guardian relationship.

## Required include/extend relationships

```text
(Register student)        <<include>> (Validate identity) (Create audit event)
                           <<extend>> (Enroll student) (Link guardian)
(Record attendance)       <<include>> (Load assigned roster) (Validate date/status)
(Save marks)              <<include>> (Load authorized roster) (Validate component) (Audit revision)
                           <<extend>> (Submit marks) (Request correction)
(AI import)               <<include>> (Validate/store file) (Queue job) (Extract) (Match) (Validate)
                           <<extend>> (Human review) (Retry/cancel)
(Approve import)          <<include>> (Revalidate) (Apply via marks engine) (Audit)
(Calculate result)        <<include>> (Load approved marks) (Apply versioned grading rules)
(Publish result)          <<include>> (Validate approvals) (Create snapshot)
                           <<extend>> (Notify recipients) (Generate marksheet)
(Generate document)       <<include>> (Authorize source) (Select template version) (Queue render)
                           <<extend>> (Public authenticity verification)
(Publish notice)          <<include>> (Validate audience/dates) (Audit)
                           <<extend>> (Notify audience)
```

## Actor relationships

```text
School administrator: broad tenant governance; delegates, does not bypass audit/lifecycle rules.
Principal: oversight and configured approval; no automatic technical administration.
Exam coordinator: examination, review, result/document authority in assigned contexts.
Teacher: assignment-scoped teaching, attendance, marks entry/import/review.
Operational staff: explicitly delegated student/document/notice operations only.
Student and parent: own/linked published information only.
Platform operator: platform operations; emergency school access is approved, time-limited, and audited.
System services: bounded processing/delivery authority only; never official academic authority.
```

## MVP mapping

MVP requires 1–18 (marksheet only for 18), 22–26, 29, and the school-scoped parts of 30. Parent/student portals, ID/admit/certificate documents, and full AI/OCR release are architecturally planned but can follow the safe core depending on the frozen release baseline.
